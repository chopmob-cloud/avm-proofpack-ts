# Handover — avm-proofpack-ts v0.1.0

**Status:** v0.1.0 complete — 10 conformance tests green on both chains.
**Repo:** `chopmob-cloud/avm-proofpack-ts`

---

## 1. Why this repo

The Python verifier is the wrong language for the consumers that matter:
wallets, browsers and exchange back-ends. Algorand ships a Go implementation
(`go-stateproof-verification`) for infrastructure; TypeScript is where the
unserved demand is.

This is the **first slice**: the consensus primitives every verifier needs, proven
byte-identical to the Python implementation rather than "close enough".

## 2. The bug this repo exists to prevent

go-codec sorts map keys by their **value**, not by their length-prefixed
encoding. `itx` sorts before `lg` (`0x69 < 0x6c`) even though the encoded form of
`lg` (`a2…`) is less than `itx` (`a3…`).

My first implementation sorted by encoded bytes and produced a different
canonical encoding — which means a different `txnId`, a different Merkle leaf and
a different block hash. The conformance suite caught it immediately against real
data. **Do not "simplify" that comparator.**

## 3. Files

- `src/msgpack.ts` — canonical encode/decode, `sha256`, `sha512_256`
- `src/avm.ts` — `txnId`, `stibHash`, `txnMerkleLeaf` (domain-separated)

- `tests/conformance.test.ts` — 10 tests against Python-generated vectors

## 4. Design decisions

1. **Zero dependencies, no build step.** Node 22.6+ strips TypeScript natively, so
   `npm test` runs `node --test` directly. Nothing to install, nothing to drift.
   This also constrains syntax: **no parameter properties** (`constructor(readonly
   x)`) — Node's strip-only mode rejects them.
2. **`str` and `bin` both decode to byte carriers.** AVM objects put arbitrary
   binary in `str` fields; decoding to a JS string and re-encoding corrupts
   non-UTF-8 data. `MpStr` wraps the raw bytes.
3. **Canonical encoding is validated, not assumed.** The test re-encodes real
   STIBs and requires byte equality with the Python output.
4. **Domain separation is explicit** (`TX`, `STIB`, `TL`) and `txnMerkleLeaf`
   refuses inputs that are not 32 bytes.

## 6. What this does NOT do (v0.1)

- No full bundle verification: block-header commitment, light-block-header proof
  and state-proof authentication are not implemented here yet.
- No Falcon-1024 verification (state proofs need it; a WASM build is the likely route).
- No browser bundle; `node:crypto` is used directly. Browser support needs
  `sha512-256`, which WebCrypto does not provide — expect a WASM hash module.

## 7. Next actions

1. Port the block-header and light-block-header commitments, then the state-proof
   message hash, extending the conformance vectors as each lands.
2. Add Falcon-1024 verification via WASM so state proofs can be checked in-browser.
3. Provide a browser-safe hash layer (WebCrypto lacks `sha512-256`).
4. Independent review (not yet done).

## 8. Constraints

- Every new primitive must be added to the conformance vectors in the same change.
- Keep both chains in the test matrix.
- No dependencies in the runtime path.
