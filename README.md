# avm-proofpack-ts

**Offline Algorand and Voi consensus verification primitives in TypeScript.**
Zero dependencies, no build step, Node 22.6+ (native TypeScript).

Byte-for-byte compatible with [`avm-proofpack`](https://github.com/chopmob-cloud/avm-proofpack)
(the validated Python implementation) on real mainnet data from **both** chains.

## What it does

| Primitive | Definition |
|---|---|
| Canonical MessagePack | shortest integer form, definite lengths, map keys sorted by key **value** |
| `txnId` | `sha256("TX" ‖ canonical(txn))` |
| `stibHash` | `sha256("STIB" ‖ stib bytes)` |
| `txnMerkleLeaf` | `sha256("TL" ‖ txid ‖ stibHash)` |
| `merkleRoot` / `merkleProof` / `verifyMerkleProof` | binary Merkle tree, odd nodes promoted |

## Why map-key ordering matters

go-codec sorts map keys by their **value**, not by their length-prefixed encoding.
`itx` sorts before `lg` even though the encoded `a2` (`lg`) is less than `a3`
(`itx`). Sorting by encoded bytes produces a different root and therefore a
different block hash — a verifier that gets this wrong rejects valid proofs, or
accepts invalid ones. This repository's conformance suite pins it.

## Use

```ts
import { decode, encode, txnId, stibHash, txnMerkleLeaf } from "avm-proofpack-ts";

const stib = decode(stibBytes);
const leaf = txnMerkleLeaf(txnId(txnValue), stibHash(stibBytes));
```

`str` and `bin` both decode to byte carriers (`MpStr` / `Uint8Array`) because AVM
objects put arbitrary binary in `str` fields; decoding to a JS string would
corrupt non-UTF-8 data on re-encode.

## Status

v0.1.0 — consensus **primitives** only. It does not yet verify a full
`avm-proofpack` bundle end to end (block-header commitment, light-header proof
and state-proof authentication are the next layer).
